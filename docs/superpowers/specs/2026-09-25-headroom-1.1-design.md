# Headroom 1.1: design spec

2026-09-25 · status: approved for build · extends `2026-09-24-headroom-design.md` (the "1.0 spec"). Section numbers written as "1.0 §2.3" refer to that file. This spec is the contract for the implementation agents. Where it is silent, the 1.0 spec still holds.

**2026-09-30 amendment (build 3):** Nio's live report led to support for explicit Codex question tool calls, which are written to rollouts. The earlier blanket “never waitingForInput” restriction below is superseded for these events only; approval dialogs without rollout events remain unsupported. Fields, acknowledgement rules, privacy limits and the native pill background fix are recorded in `docs/handoffs/2026-09-30-codex-input-and-pill.md`.

**Evidence tags** on decisions: **[V-codex]** verified against the 614 local Codex rollouts or the upstream openai/codex source; **[V-gh]** verified in GitHub docs, the OpenAPI description or read-only `gh api` GETs; **[V-apple]** verified in the macOS 27 SDK, Xcode specs or Apple docs; **[V-repo]** verified in this repo; **[R]** reported by third parties and not reproduced here; **[I]** inferred; **[J]** judgment call. Every synthetic example uses made-up values.

## 0. Scope

1.1 turns the website's three "Coming soon" cards into shipped features, under 1.0's rules: sandboxed, honest, no other app's login tokens, and nothing guessed.

| # | Feature | Ships when | Network |
|---|---|---|---|
| F1 | **OpenAI Codex**: limits (1 or 2 rings), running sessions (working / idle), context bars, from `~/.codex` read-only | always (must ship) | none |
| F2 | **GitHub Copilot usage**: this month's AI credits (or legacy premium requests) through Headroom's own GitHub App (device flow, `Plan: read`) | gate **G1** passes (§4.8) | `api.github.com`, `github.com`, only after the user connects |
| F3 | **Copilot CLI sessions**: working / needs you / idle through Copilot CLI's documented user hooks ("Connect Copilot CLI") | gate **G2** passes (§4.9) | none |
| F4 | **Widgets**: Limits (small, medium) and Sessions (medium, large) for the desktop and Notification Center | always (must ship) | none |
| F5 | Multi-tool pill, panel and Settings ("Rings show", optional "One gauge per tool", Settings tabs) | always | none |

"Copilot" leaves "Coming soon" if F2 or F3 ships. If neither ships, 1.1 ships F1 + F4 + F5, the website keeps a Copilot card marked "Coming soon", and the App Store text does not mention Copilot.

**Not in 1.1:** VS Code Copilot Chat sessions (undocumented op-log format with full prompts; 1.2 candidate) [V-gh local structure]; "Needs you" for Codex, because approval requests are never written to rollouts [V-codex policy.rs]; Codex app-server, IPC socket or SQLite [V-codex: experimental; WAL files fail read-only opens]; `api.github.com/copilot_internal/*` and any token taken from gh, VS Code or the Copilot CLI (undocumented, and would reuse another app's token) [V-gh]; usage on organization Copilot seats (no individual endpoint exists) [V-gh]; widget buttons (App Intent actions) and `systemExtraLarge`; Codex credit balances.

### 0.1 Invariants (every stream)

1. **Claude-only users see 1.0.** When Codex and Copilot are not tracked, the pill and panel render pixel-identical to 1.0 (golden test, §11.3). 1.0 preference keys, bookmark keys, the Claude bridge and `BridgeScript.version` stay unchanged.
2. **Read-only for other tools' data.** CodexKit opens only the paths in §3.1. It never opens `auth.json`, `config.toml`, `models_cache.json`, `.codex-global-state.json`, `*.sqlite*` or `ipc/`, and never calls `flock` [V-codex writer_lock.rs: a shared lock would break Codex's `try_lock`].
3. **Headroom uses only its own credentials.** The GitHub token comes from Headroom's own device flow and lives in Headroom's own Keychain item. Only the main app reads it. The widget never does.
4. **Prompt text is never persisted.** Codex: decode only the fields listed in §3.2. Copilot CLI bridge: ids, paths, event names and notification types only.
5. **The widget never reads user folders.** The app is the only writer of the shared file (§5).
6. **No trustworthy number, no number.** Every reading has an `observedAt` and shows "as of" when it is stale. An unknown format becomes an issue or status, never a guess.

## 2. Model changes (HeadroomModel)

### 2.1 New types (`Sources/HeadroomModel/Tools.swift`)

```swift
public enum ToolID: String, Sendable, Codable, CaseIterable, Hashable {
    case claude, codex, copilot                       // fixed display order everywhere
    public var shortName: String { ... }              // "Claude", "Codex", "Copilot"
    public var fullName: String { ... }               // "Claude", "OpenAI Codex", "GitHub Copilot"
}

public enum WindowKind: Sendable, Codable, Hashable {
    case fiveHour, daily, weekly, monthly
    case minutes(Int)
    /// 240...360 → fiveHour, 1200...1680 → daily, 9000...11000 → weekly, 40000...46000 → monthly, else .minutes(n).
    public init(windowMinutes: Int)
    public var title: String      // "5-hour", "Daily", "Weekly", "Monthly", "3-hour", "2-day"
    public var lengthMinutes: Int // 300, 1440, 10080, 43200, n
}

public enum UsageUnit: String, Sendable, Codable { case aiCredits, premiumRequests }

public struct ToolLimit: Sendable, Equatable, Codable {
    public var window: WindowKind
    public var usedPercent: Double?     // nil = allowance unknown (Copilot "Not sure"): no ring fill, no percent
    public var used: Double?            // absolute amount (Copilot)
    public var allowance: Double?       // Copilot plan allowance
    public var extra: Double?           // Copilot billed extra usage (Σ netQuantity), > 0 only
    public var unit: UsageUnit?
    public var resetsAt: Date?
    public var resetIsEstimated: Bool
    public var resetSinceReading: Bool  // rollover applied (§3.4): "reset since last reading"
    public var observedAt: Date
    public func rolledOver(now: Date) -> ToolLimit
}

public struct NamedLimits: Sendable, Equatable, Codable { public var id: String; public var name: String; public var limits: [ToolLimit] }

public enum ToolStatus: String, Sendable, Codable {
    case ok, needsAccess, noActivity, unrecognized                        // Codex
    case notConnected, signInExpired, noIndividualUsage, offline, rateLimited  // Copilot usage
}

public struct ToolUsage: Sendable, Equatable, Codable {
    public var tool: ToolID
    public var limits: [ToolLimit]        // longest window first
    public var hasFiveHourWindow: Bool    // the plan's shape: draw the inner ring track (§6.1)
    public var otherBuckets: [NamedLimits]// Codex buckets other than "codex" (e.g. Spark)
    public var status: ToolStatus
    public var planName: String?          // Codex plan_type ("Plus", "Pro", "Pro Lite"); Copilot preset ("Pro+")
    public var account: String?           // Copilot GitHub login
    public var staleAfter: TimeInterval   // Codex 30 min, Copilot 45 min [J]
    public var newestObservation: Date? { get }
    public var tightest: ToolLimit? { get }   // highest non-nil usedPercent
    public func isStale(now: Date) -> Bool
    /// Claude's PlanUsage as a ToolUsage (weekly, fiveHour; hasFiveHourWindow true; staleAfter 30 min) for
    /// compact rows, multi-tool pills and widgets. The Claude-only header keeps using PlanUsage directly.
    public init(claude plan: PlanUsage)
}
```

`ToolLimit.rolledOver(now:)`: when `resetsAt <= now`: 5-hour → `usedPercent 0, used 0, resetsAt nil`; monthly (Copilot) → `used 0, usedPercent 0 (if allowance), resetsAt = next month's 1st 00:00 UTC`; any other window → `usedPercent 0, resetsAt nil, resetSinceReading true`. Codex never gives the next weekly reset after one passes [V-codex: readings exist only after use], so it is not invented.

## 3. OpenAI Codex (CodexKit)

### 3.1 Access

- Folder `~/.codex` (`RealHome/.codex`), granted in an open panel, bookmarked **read-only** (`securityScopeAllowOnlyReadAccess`), key `folderBookmark.codex`. The picker also accepts any folder that contains a `sessions/` subfolder, since a sandboxed app can't read the `CODEX_HOME` environment variable [V-codex]. The existing `user-selected.read-write` entitlement covers it [V-repo].
- **Codex installed** = `~/.codex` exists (`AccessProbe.isMissing` is false) or an app with bundle id `com.openai.codex` is installed (`/Applications/ChatGPT.app`) [V-codex].
- Rejected: granting only `~/.codex/sessions`. It would hide `auth.json` by structure, but it loses lock-based liveness, titles and import exclusion [V-codex]. The allowlist plus a source test (§11.1) enforces the rule instead [J].

| `CodexPaths` member | Path | Use |
|---|---|---|
| `sessionsDirectory` | `sessions/**/rollout-*.jsonl` | walk, stat, head and tail reads |
| `sessionIndexFile` | `session_index.jsonl` | titles (tail read) |
| `importsFile` | `external_agent_session_imports.json` | import exclusion (whole file, ≤ 4 MB, else ignored) |

### 3.2 Formats (synthetic; one JSON object per line)

Layout `sessions/YYYY/MM/DD/rollout-<local ts>-<thread uuid>[_<rollout uuid>].jsonl`. The day folder and filename use **local** time; line `timestamp`s are UTC ISO-8601 with milliseconds. The thread id is a UUIDv7: its first 48 bits are the creation epoch-ms [V-codex 614/614]. Filename regex: `^rollout-(\d{4}-\d\d-\d\dT\d\d-\d\d-\d\d)-([0-9a-f-]{36})(?:_([0-9a-f-]{36}))?\.jsonl$`.

```json

{"timestamp":"...","type":"turn_context","payload":{"turn_id":"t1","cwd":"/Users/me/code/app","model":"gpt-6-astra","effort":"high"}}
{"timestamp":"...","type":"event_msg","payload":{"type":"task_started","turn_id":"t1","started_at":1790170000,"model_context_window":258400}}
{"timestamp":"...","type":"event_msg","payload":{"type":"task_complete","turn_id":"t1","started_at":1790170000,"completed_at":1790170420,"last_agent_message":"<never read>"}}

```

`rate_limits` variants to decode [V-codex counts]:

| Variant | Shape |
|---|---|
| Pro / Pro Lite (most common) | `codex`, primary `{42.0, 10080, resets_at}`, secondary null: **weekly in `primary`** |
| Plus | `codex`, primary `{17.0, 300, …}`, secondary `{55.0, 10080, …}` |
| Spark bucket | `limit_id "codex_bengalfox"`, `limit_name "GPT-5.3-Codex-Spark"`, 300 + 10080 |
| No windows | `limit_id "premium"`, primary null, secondary null |
| API key / proxy / imported | `"rate_limits": null` |
| Legacy v0.46–0.49 | window `{"used_percent":12.5,"window_minutes":300,"resets_in_seconds":7200}` → resetsAt = line ts + s |
| Legacy ~v0.40 flat | `{"primary_used_percent":12.5,"secondary_used_percent":40.0,"primary_window_minutes":300,"secondary_window_minutes":10080}` → resetsAt nil |

Decoding is lenient: every field optional; `used_percent` as Double; `resets_at` epoch seconds (a 13-digit value is read as milliseconds, defensively [J]); a missing `limit_id` means `"codex"`; a missing `window_minutes` means primary = 300 and secondary = 10080 (Codex's own fallback) [V-codex]. Lifecycle aliases `turn_started` and `turn_complete` are accepted [V-codex].

Side files:
```json
{"id":"01a0beba-55ec-7ac1-84a7-16d9f0a456e0","thread_name":"Fix login bug","updated_at":"2026-09-21T02:18:03.145384Z"}
{"records":[{"source_path":"/Users/me/.claude/projects/-Users-me-app/<uuid>.jsonl","imported_thread_id":"<codex uuid>","imported_at":1789900000,"title":"<never read>"}]}
```
The first line is `session_index.jsonl`: append-only, and the newest line per id wins. The second is `external_agent_session_imports.json`. `thread-writer-locks/<thread id>.lock` exists while a Codex process has that thread loaded, and `.coordination.lock` is always ignored [V-codex].

### 3.3 Reading strategy

- **Walk** `sessions/` at launch, then at most every 30 s or when the set of lock files changes. Keep `path → (inode, size, mtime, head meta, tail state)` in a bounded cache (64 entries, LRU; reuse `ContextKit.BoundedCache`). Files `.jsonl.zst` are ignored: they are cold history [V-codex: compression is off by default and only applies after 7 days].
- **Head read** once per file: read 64 KB, grow to 1 MB until the first `\n`, then decode `session_meta` (the first line is 19–23 KB) [V-codex].
- **Tail read** with the new `ContextKit.JSONLTailReader`: last 256 KB, growing ×4 up to 8 MB, newest line first. Before JSON-decoding a line, match it by substring against `"token_count"`, `"task_started"`, `"task_complete"`, `"turn_aborted"`, `"turn_started"`, `"turn_complete"`, `"turn_context"` and `"thread_settings_applied"`, and skip lines over 4 MB. On an unchanged inode with a bigger size, read only the appended bytes and keep the last good value per file. Rollouts reach 4 GB [V-codex: p99 17.9 MB, max 4.01 GB]. Never read a whole file.
- **2-second poll budget:** list `thread-writer-locks/`, stat the live threads' rollouts and stat both side files. Tail-read only what changed.
- **October 1, build 8 amendment — lifecycle recovery:** a live native root session can start before the last 8 MB. When its lifecycle is absent, continue backwards in bounded windows, with a separate 32 MB history-read budget per poll and a cached continuation offset. Continue even when the file is unchanged; stop once the newest start/end event is found. Apply the same recovery to append gaps larger than a tail window so a missed completion cannot leave a task working. Retain the newest values by timestamp, the 4 MB line limit and minimal field decoding. Once recovered, unchanged polls open no rollout files. Extremely long histories can take multiple polls; never load the whole file into memory.

### 3.4 Plan limits

Codex rollouts are rewritten, which bumps old files' mtime [V-codex: up to 3.76 h late; openusage#371], so the newest reading is found by the event's own timestamp:

```
files = rollouts sorted by mtime, newest first
best  = [:]   // limit_id -> (timestamp, RateLimitSnapshot)
for f in files:
    if let b = best["codex"], f.mtime < b.timestamp - 1 s { break }   // mtime >= last event time held on 614/614 [V-codex]
    for line in tail(f) newest first where type == token_count && rate_limits != null:
        id = rate_limits.limit_id ?? "codex"; keep in best[id] if newer
```

Include subagent rollouts, which carry readings too [V-codex], but not imported ones.

Mapping to `ToolUsage(tool: .codex)`:
- Rings use only the `codex` bucket. Each non-null window maps by `WindowKind(windowMinutes:)`, from primary or secondary alike (never "primary means 5-hour") [V-codex]. `limits` is sorted with the longest window first. `hasFiveHourWindow` is true when the newest `codex` snapshot has a ≈300-minute window.
- `observedAt` = that line's `timestamp`. `resetIsEstimated` is false. Apply `rolledOver(now:)` on every build [V-codex: readings seen up to 1 min past `resets_at`].
- Other buckets with at least one window go to `otherBuckets` (name = `limit_name ?? limit_id`). Buckets with only null windows (`premium`) are ignored.
- `planName` comes from `plan_type`: plus → "Plus", pro → "Pro", prolite → "Pro Lite", anything else capitalized, null → nil.
- Status: `.ok` with a reading. `.noActivity` when no rollout has a non-null `rate_limits`; the panel then says "No Codex limits found", since this user is probably on an API key. `.unrecognized` plus `DataIssue.codexUsageUnrecognized` when the newest non-null `rate_limits` decodes to no window and isn't a known empty bucket. The last good reading is kept for 5 minutes first, as 1.0 §2.1 does.
- `staleAfter` = 30 min, the same dimming rule as Claude [J; Codex itself uses 15 min, V-codex].
- `task_complete.error.codex_error_info == "usage_limit_exceeded"` is ignored in 1.1, and `rate_limit_reached_type` too (null in all 28,180 readings) [V-codex]. Headroom shows Codex's numbers as they are.

### 3.5 Sessions

**Which threads.** Root, native threads only:
- Keep `thread_source == "user"`, or `thread_source` missing with `source` ∈ {`"cli"`, `"vscode"`}.
- Exclude subagent objects, `guardian_review`, `exec` (`codex exec` is automation, like 1.0's `sdk-cli` exclusion) and `mcp`.
- Exclude ids in `imported_thread_id`, unless the rollout has a `turn_context` newer than `imported_at` (the user continued the import inside Codex). Otherwise 463 imported Claude transcripts would double-count Claude sessions [V-codex].

**Liveness.** `codexRunning` = an app with bundle id `com.openai.codex` is running (NSWorkspace, injected by the app) OR any process with `p_comm == "codex"` exists (`sysctl KERN_PROC_ALL`). The Desktop app runs a `codex` child too [V-codex]. It is `nil` when the process list can't be read in the sandbox [I, verify L4].

| `thread-writer-locks/` | `<id>.lock` | `codexRunning` | Shown |
|---|---|---|---|
| exists | present | true | yes |
| exists | present | false | no (a lock left behind by a crash) [V-codex] |
| exists | present | nil | if newest event < 2 h old [J] |
| exists | absent | any | no |
| missing (older Codex) | n/a | true / nil | if newest event < 15 min old [J] |
| missing | n/a | false | no |

A shown **idle** thread whose newest event is older than 8 h is hidden: the Desktop app may keep threads loaded for a long time [I; tune after live check L2].

**Activity.** Working when the newest lifecycle event is `task_started` (or `turn_started`) with no later `task_complete`, `turn_complete` or `turn_aborted` for its `turn_id`; otherwise idle. `activitySince` is that event's timestamp. Never `waitingForInput` [V-codex].

**Context.** From the newest `token_count` with `info != null` in the thread's tail: `usedTokens = info.last_token_usage.total_tokens`; `windowTokens = info.model_context_window ?? task_started.model_context_window`; `baselineTokens = 12000`. The percent is Codex's own: `clamp(max(0, used − 12000) / (W − 12000), 0, 1)` [V-codex status_controls.rs]. The value can reach 105.6 % before auto-compaction, hence the clamp. Estimate lines (input and output 0, total set) are valid. Never use `total_token_usage`, which is cumulative. With no window known, use 258,400 with `windowIsAssumed = true`, so the panel shows tokens only. `windowIsExact` is true when the window came from `info`. `model` = newest `turn_context.model`, else `thread_settings_applied.thread_settings.model`.

**Naming and origin.**
- Name: the newest `session_index` `thread_name` (trimmed, non-empty), else the `cwd` basename.
- When two shown Codex rows share a name, append ` · 2:14 PM` (their `startedAt`, local short time).
- Never use user message text.
- Origin: `source == "cli"` → `.terminal` (terminal symbol), else `.desktop`. `projectPath` = `cwd`, `startedAt` = `session_meta.timestamp`, `pid` nil, `transcriptPath` nil.
- Finding a known thread's file: decode the UUIDv7 milliseconds and look in that local day's folder, then the neighbouring days (midnight and time zone changes) [V-codex].

| Not allowed | other `copilot_internal/*` endpoints, tokens from gh / VS Code / Copilot CLI (`config.json`, `~/.config/github-copilot`, `state.vscdb`), log scraping, classic PAT as the main path | undocumented, or reuses another app's login |

Known limits, all shown honestly:
- Organization-managed seats (Business, Enterprise) are invisible to the billing endpoints [V-gh]; only the organization-seat fallback above can show them.
- No API returns the allowance, so the user picks a plan (§4.5) [V-gh].
- Billing data lags by an unpublished delay [I], so readings show "as of".

### 4.3 Device flow and tokens (CopilotKit `DeviceFlow`, `TokenRefresher`)

```
POST https://github.com/login/device/code?client_id=Iv23liEXAMPLE          Accept: application/json
→ {"device_code":"3584d8…","user_code":"WDJB-MJHT","verification_uri":"https://github.com/login/device","expires_in":900,"interval":5}
POST https://github.com/login/oauth/access_token?client_id=Iv23liEXAMPLE&device_code=3584d8…&grant_type=urn:ietf:params:oauth:grant-type:device_code
→ {"error":"authorization_pending"} | {"error":"slow_down"} (+5 s) | expired_token | access_denied | device_flow_disabled | incorrect_client_credentials
→ {"access_token":"ghu_EXAMPLE","expires_in":28800,"refresh_token":"ghr_EXAMPLE","refresh_token_expires_in":15897600,"token_type":"bearer","scope":""}
POST https://github.com/login/oauth/access_token?client_id=Iv23liEXAMPLE&grant_type=refresh_token&refresh_token=ghr_EXAMPLE   (no secret) → same shape, both tokens rotate
GET  https://api.github.com/user   → {"login":"octocat","id":1,"type":"User"}
```

- Poll at `interval`, adding 5 s on each `slow_down`. Give up at `expires_in`.
- Refresh when `accessExpiresAt − 5 min < now`, or once on a 401, then retry the request once. Save the rotated pair atomically as one Keychain item before using it.
- `bad_refresh_token` or a refresh token past expiry → status `.signInExpired`.
- **Only the main app** refreshes. There is one `CopilotService` actor.
- Keychain: `kSecClassGenericPassword`, service `com.niomartinez.headroom.github`, account `default`. The value is JSON `{"access":"ghu_…","refresh":"ghr_…","accessExpiresAt":1790000000,"refreshExpiresAt":1805000000}`, not synchronizable. Try the data-protection keychain first (`kSecUseDataProtectionKeychain`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`). On `errSecMissingEntitlement` (−34018, ad-hoc builds) fall back to the login keychain [I, Apple TN3137].
- The login is kept in UserDefaults `copilotLogin` for display. Tokens are never logged, printed, written to the widget file or put in URLs.
- CopilotKit takes a `TokenStore` protocol (in-memory in tests) and an injected `URLSession`/`HTTPTransport`. Every request sends `User-Agent: Headroom/<version> (macOS)`.
- **Disconnect** deletes the Keychain item and `copilotLogin`, then offers `https://github.com/settings/apps/authorizations`. Revoking the grant server-side needs a client secret, which Headroom doesn't have [V-gh].

### 4.4 Usage fetch (CopilotKit `UsageClient`)

```
GET https://api.github.com/users/octocat/settings/billing/ai_credit/usage?year=2026&month=9
Authorization: Bearer ghu_…   Accept: application/vnd.github+json   X-GitHub-Api-Version: 2026-03-10
→ {"timePeriod":{"year":2026,"month":9},"user":"octocat","usageItems":[
   {"product":"Copilot AI Credits","sku":"AI Credit","model":"GPT-5","unitType":"ai-credits","pricePerUnit":0.01,
    "grossQuantity":412.5,"grossAmount":4.125,"discountQuantity":412.5,"discountAmount":4.125,"netQuantity":0,"netAmount":0}]}
```

- Year and month are the **UTC** month of `now`. The reset is exact: the next 1st at 00:00:00 UTC [V-gh].
- Credits: sum the items whose `unitType`, lowercased with `_` turned into `-`, is `ai-credits`. `used = Σ grossQuantity`, `extra = Σ netQuantity` (billed beyond the included amount) [V-gh billing reports]. Legacy: `premium_request/usage`, `unitType` `requests`, same sums.
- Unit detection: legacy presets query `premium_request`. Otherwise query `ai_credit`, and when it returns 200 with no matching items, query `premium_request` at most once an hour; use whichever has items.
- Result: `ToolUsage(tool: .copilot, limits: [ToolLimit(window: .monthly, used:, allowance:, extra:, unit:, usedPercent: allowance.map { used / $0 * 100 }, resetsAt:, resetIsEstimated: false, observedAt: fetch time)], hasFiveHourWindow: false, account: login, staleAfter: 45 min)`.
- Real strings are confirmed in G1. The decoder tolerates missing `product` and `model` [V-gh OpenAPI: optional].

### 4.7 Polling

- Poll every 15 min while tracking is on and connected.
- Also poll when the panel opens and the last success is more than 5 min old, and once after wake.
- Errors back off 1 → 2 → 4 → … → 60 min. 403/429 wait for `Retry-After` (else `x-ratelimit-reset`).
- At most 18 requests an hour (6 polls of up to 3: `ai_credit`, `premium_request` and the organization seat; 12 before 2026-10-02) against the user's 5,000/h REST budget [V-gh]. No polling in sample data mode.
- The device-flow limit is 50 code submissions per hour per app [V-gh, OAuth Apps doc]. On `slow_down` storms or HTTP 429 during sign-in, show "GitHub is busy. Try again in a few minutes."

### 4.8 Gate G1 and the fallback

**G1** (after O1, about 10 minutes with Nio at the keyboard):
1. Run `scripts/dev/github-device-login.sh` (new, dev-only, never bundled). It runs §4.3 with the Client ID and keeps the token only in a shell variable.
2. The script calls `/user` and both usage endpoints and prints: status codes, the `X-Accepted-GitHub-Permissions` header, the item count and the distinct `(product, sku, unitType)` triples. It never prints the token or any quantities.
3. G1 passes when the ai_credit endpoint returns **200** for a GitHub App user token.
4. Record the results in RELEASE-STATUS.md. Nio's own Copilot may be organization-paid, in which case an empty 200 is still a pass [I].

**Build switch.**
- `HEADROOM_GITHUB_CLIENT_ID` (project.yml) → Info.plist `HeadroomGitHubClientID`.
- Empty → CopilotService is inert: no Connect button, the Copilot section shows only F3 (if shipped), and no network code runs.
- `com.apple.security.network.client` is in the Release entitlements **if and only if** the Client ID is non-empty. `scripts/verify-build.sh` fails the release otherwise.
- **Fallback if G1 fails or O1 isn't done in time:** ship with an empty Client ID. Copilot then ships as F3 only (local, still "no network"), or stays "Coming soon" if G2 also fails. A fine-grained PAT paste is not a fallback: the docs conflict on whether it works [V-gh], and it teaches users to paste tokens [J].

### 4.9 Copilot CLI sessions (F3, gate G2)

- Folder `~/.copilot` (or a folder the user picks for `$COPILOT_HOME`), **read-write**, requested only when the user clicks **Connect Copilot CLI**. Bookmark key `folderBookmark.copilotCLI`.
- `CopilotPaths` allows only: write `hooks/headroom.json` and `headroom/**`; read `headroom/sessions/*.hook.json`; list `logs/` (names only).
- Never open `config.json` (it can hold auth), `settings.json`, `session-state/` or `session-store.db` [V-gh docs].

`~/.copilot/hooks/headroom.json`: its own file, so the user's settings stay untouched [V-gh hooks reference]. The same no-op guard as 1.0 §2.6:
```json
{"version":1,"hooks":{
 "sessionStart":[{"type":"command","bash":"[ ! -f \"$HOME/.copilot/headroom/bridge.sh\" ] || exec /bin/bash \"$HOME/.copilot/headroom/bridge.sh\" hook","timeoutSec":5}],
 "userPromptSubmitted":[…same…],"postToolUse":[…],"notification":[…],"agentStop":[…],"sessionEnd":[…]}}
```
**Never register `preToolUse`**: command preToolUse hooks fail closed and would block the user's tools [V-gh].

The bridge (`~/.copilot/headroom/bridge.sh`, header `# headroom-copilot-bridge v1`) follows 1.0 §2.5:
- Always exits 0, prints nothing, finishes in < 100 ms and reads stdin once.
- Extracts `sessionId`, `cwd` and `notification_type` with a bash regex (camelCase and snake_case both). Writes are atomic.
- Is a no-op once Headroom is uninstalled (1.0 §2.4 rule).
- Writes `~/.copilot/headroom/sessions/<sessionId>.hook.json`:
```json
{"v":1,"ts":1790250200,"event":"notification","session_id":"<uuid>","cwd":"/Users/me/app","notification_type":"permission_prompt","pids":[[12345,"node"],[12300,"copilot"]]}
```

| Hook event | Activity |
|---|---|
| `userPromptSubmitted`, `postToolUse` | working |
| `notification` with `permission_prompt` or `elicitation_dialog` | waitingForInput |
| other `notification`, `agentStop`, `sessionStart` | idle |
| `sessionEnd` | delete `sessions/<id>.*` |

Liveness: the Copilot process is the first pid in `pids` (up to 6 ancestors, from `ps -o ppid=,comm=`) that has a `~/.copilot/logs/process-<epochMs>-<pid>.log` whose `epochMs` is within 2 s of that pid's start time (`ProcessProbe.startTime`). The log naming is documented [V-gh]. The session is shown while that pid is alive. With no such match, it is shown while its newest `ts` is < 30 min old (1.0 §2.5). Name: the `cwd` basename. Origin `.terminal`, tool `.copilot`, no context bar in 1.1 (the statusLine payload is undocumented [V-gh]).

Connect and Disconnect mirror 1.0 §2.6:
- A confirmation dialog lists every change before anything is written.
- Disconnect removes exactly `hooks/headroom.json` and `headroom/`, renaming the folder before deleting it.
- State detection reports installed, outdated, not installed or unreadable.
- New hooks apply to sessions started after connecting.

**G2** passes when:
1. The bridge tests pass, run with `HOME` set to a temp dir and payload fixtures.
2. One live check with Copilot CLI (Nio installs it; it is a download, so ask first) shows that user hooks in `~/.copilot/hooks/` fire, the payload field names match, `notification` arrives with `permission_prompt`, and a `logs/process-*` file exists for the session.

If G2 fails, S3's code stays compiled out (Swift condition `HEADROOM_COPILOT_CLI` off) and nothing about Copilot CLI appears anywhere.

## 5. Widgets (F4)

### 5.1 Architecture

The folder grants are app-scoped bookmarks tied to the app's bundle id, so the widget extension can't resolve them [V-apple, CVE-2025-31191 analysis]. **The app is the only writer.** It writes a scrubbed snapshot to its App Group container, and the extension only decodes that file.

- **App Group:** `$(TeamIdentifierPrefix)com.niomartinez.headroom`, which is `L237BMXGB6.com.niomartinez.headroom`.
  - Team-prefixed IDs need no registration on macOS [V-apple].
  - It passes macOS 15 container protection by team prefix and by Mac App Store distribution [V-apple DTS 721701].
  - `REGISTER_APP_GROUPS` stays NO.
  - The file is a rebuildable cache, so switching to `group.*` later is cheap [J].
- **Only team-signed builds claim the group.** A group claimed without a Team ID is rejected, the widget exits, and the app can hang [R: CodexBar #318, #533].
  - Setting `HEADROOM_APP_GROUP` (default NO) picks `X.entitlements` or `X-NoGroup.entitlements` through `HEADROOM_GROUP_SUFFIX_$(HEADROOM_APP_GROUP)`.
  - YES comes from `Config/Signing.local.xcconfig` and from `fastlane mac build`. `fastlane mac check`, Debug and ad-hoc Release builds use NO.
  - At runtime, `WidgetShare.groupIdentifier()` returns non-nil only if Info.plist names the group **and** the process's signed entitlements contain it (`SecTaskCopyValueForEntitlement`). So Debug builds never touch or prompt for the container.

### 5.2 Target (project.yml, owned by S6)

`HeadroomWidgets`:
- `type: app-extension` (a real Xcode product type; a SwiftPM executable wrapped by hand exits on macOS 26 [R CodexBar #1095]). `platform: macOS`, deployment target 14.0 inherited.
- `PRODUCT_BUNDLE_IDENTIFIER com.niomartinez.headroom.widgets`, `SKIP_INSTALL YES`.
- `INFOPLIST_FILE Widgets/Info.plist`, with `NSExtensionPointIdentifier com.apple.widgetkit-extension` and no principal class. It also carries `HeadroomAppGroup = $(TeamIdentifierPrefix)com.niomartinez.headroom` and the copyright string from §8.
- `configFiles` are the app's xcconfigs, so signing matches.
- Entitlements `Widgets/HeadroomWidgets$(HEADROOM_GROUP_SUFFIX).entitlements`: `app-sandbox`, plus `application-groups` in the group variant. `CODE_SIGN_INJECT_BASE_ENTITLEMENTS NO` in Release.
- Depends on the package product `HeadroomWidgetKit`.
- The app target lists `- target: HeadroomWidgets` as a dependency, which embeds it in `Contents/PlugIns` [V-apple XcodeGen source].
- Versions live only in project settings: `MARKETING_VERSION 1.1.0`, `CURRENT_PROJECT_VERSION 2`. Never set them on the extension; the app and extension must match [V-apple].
- The app's `App/Info.plist` gains `HeadroomAppGroup` and `CFBundleURLTypes` with the scheme `com.niomartinez.headroom`. Other "Headroom" apps exist, so a unique scheme is needed [V-repo].

### 5.3 Shared file (HeadroomShare)

**Scrubbing** before writing:
- Sessions: `pid`, `transcriptPath` and `projectPath` are set to nil. `name` becomes `""` when `showsSessionNames` is false. Keep at most 12 sessions, in display order.
- Encoding: `.secondsSince1970`, written atomically (temp file + rename).

### 5.4 Publishing (App, owned by S6: `App/Sources/Model/WidgetPublisher.swift`, `App/Sources/Logic/WidgetReloadGate.swift`)

- `actor WidgetPublisher { func publish(_ snapshot: HeadroomSnapshot, isSample: Bool, pillTool: ToolID?, showsNames: Bool, now: Date) }` runs off the main thread. AppModel calls it after each applied poll and from `showSample()`. `--render-live` never calls it.
- `WidgetSignature` (pure) holds what the widgets show:
  - Per tool: the rounded percent and severity of each limit, and the status.
  - `activeCount`, `waitingCount`, and the top 7 sessions as (id, activity, context rounded to 5 %).
  - `issues`, `isSample`, `pillTool`, `showsSessionNames`.
- `WidgetReloadGate.decide(previous:current:now:) -> (write: Bool, reload: Bool)`:
  - Write when the signature changed, or on a 15-minute heartbeat.
  - Normal reloads come at least 10 min apart.
  - **Urgent** reloads come at least 2 min apart, at most 6 an hour. Urgent means a severity change, "needs you" appearing or clearing, sample mode toggled, an access change, the first write after launch, or wake.
  - Apple's budget is about 40–70 reloads a day, and app-requested reloads draw on it [V-apple].
- A reload calls `WidgetCenter.shared.reloadTimelines(ofKind:)` for both kinds.

### 5.5 Timeline (HeadroomShare `WidgetTimelinePlan`, extension provider)

- Entries every 5 min for 60 min, plus each limit's `resetsAt` and each `observedAt + staleAfter` within 6 h. Dates are sorted and at least 60 s apart.
- Policy `.after(now + 20 min)` while `writtenAt` is under 20 min old, else `.after(now + 60 min)`.
- Each entry rebuilds its models at `entry.date` after `rolledOver(now: entry.date)`, so a reset limit drops to 0 without a reload.
- `placeholder` and gallery `getSnapshot` (`context.isPreview`) use `SampleData(now:)`.
- `TimelineEntryRelevance` is unused: it has no effect on macOS [V-apple].

## 6. UI and UX

### 6.1 Pill

- **Single gauge (default).** The pill shows one tool, chosen by **Rings show**:
  - Automatic (the default) = the first tracked tool, in the order Claude → Codex → Copilot, that has a limit with a percent. If none has one, the first tracked tool (tracks only).
  - It never follows whichever tool is tightest, so the rings don't jump [J].
  - Upgrading Claude users therefore see Claude, exactly as in 1.0.
- **Rings.** Outer = the longest window; inner = the 5-hour window. When `hasFiveHourWindow` is false (Codex Pro weekly-only, Copilot monthly), only the outer ring is drawn (r 7, line width 2) with **no inner track**, so it can't read as "5-hour 0 %" [V-repo: an empty track means "no reading" today].
- **Number, dot and count.** The number is the shown tool's tightest percent, only at ≥ 75 %. The dot and count cover the sessions of **all** tracked tools.
- **One gauge per tool** (opt-in):
  - One 18 pt gauge per tracked tool with limits, in fixed order, 5 pt apart.
  - **October 1, build 9 amendment (Nio):** each gauge shows its own tool's highest rounded percent at ≥ 75 %, immediately after that gauge. Simultaneous and tied warnings all show their percentages. This replaces the original single-highest-number rule.
  - Each gauge dims on its own tool's staleness. Width includes every visible warning percentage, so it can exceed the original 143 pt estimate. Automatic preserves the selected gauges and their numbers; explicit Always compact keeps one selected gauge.
- **Accessibility.** Claude-only keeps the 1.0 label. With several tools: "3 active sessions. Claude weekly 89%, 5-hour 14%. Codex weekly 94%. Copilot 34% of monthly credits." The status item tooltip is the same text without the session part.

### 6.2 Moments

Layout, the 4 s duration, the queue and the 212 pt text cap are unchanged.

| Event | 1 tool tracked | 2+ tools tracked |
|---|---|---|
| Session finished / needs you | `ledger finished` / `harbor needs you` (never the tool; VoiceOver: "Codex session ledger finished") | same |
| Limit crossing 90 | `Weekly at 90%` | `Codex weekly at 90%`, `Claude 5-hour at 90%` |
| Limit reaching 100 | `Weekly limit reached` | `Codex weekly limit reached` |
| Copilot 90 / 100 | `Monthly at 90%` / `Monthly credits used up` | `Copilot monthly at 90%` / `Copilot credits used up` |

`toolLimitCrossed` follows 1.0 §3.4 guards per `(tool, window)`:
- Both snapshots have the limit, the new one is a newer observation, and it rose ≤ 25 points.
- No moment on the first snapshot, or when `planName`/`account` changed between snapshots (an account switch).
- Copilot reaching 100 % says "used up", because Copilot keeps working on paid extra usage [V-gh].
- Codex sessions produce `sessionFinished` when a turn completes (working → idle, ≥ 5 s).

### 14.1 Stale "needs you" (note 1) [V-local]
Root cause: a live terminal `claude` (CLI 2.1.281) parked on a startup nudge dialog. Claude Code writes `status:"waiting"`, `waitingFor:"dialog open"` to `~/.claude/sessions/<pid>.json` 7.7 s after launch and never again. 1.0 maps any status containing "wait" to Needs you and ignores `waitingFor`. The terminal bridge was not installed. Fixes (app-side only; no bridge change, `BridgeScript.version` stays 5):
- `RegistryEntry` parses `waitingFor` and `version`. `ActivityMapping.registryStatus(_:waitingFor:startedAt:statusUpdatedAt:)`: `waiting` + `waitingFor == "dialog open"` + (statusUpdatedAt − startedAt) < 60 s → **idle**; any other waiting → needs you. Unknown `waitingFor` values keep the 1.0 behaviour.
- Bridge Notification types: needs you = `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, `agent_needs_input`, or a missing/empty type (old CLIs). `elicitation_complete`, `elicitation_response` → working. `idle_prompt`, `auth_success`, `agent_completed`, `quota_auto_resume_*` and unknown types → idle.
- 1-second rule: when the registry entry reports waits itself (`waitingFor` present or version ≥ 2.1.281), a registry status at or after the notification's second counts as newer.
- `SessionMerger+Bridge`: `activitySince = record.lastEventAt ?? record.lastSeenAt`, so status-line writes don't restart a waiting episode.
- Update 1.0 spec §2.2 and §2.5 to match.

### 14.10 Pill: findings and design (S9)
- **Ring centring (note 4) [V-repo, measured].** In 1.0 each ring was a `Circle` in a frame of its own diameter, centred in the gauge. The inner ring's 7 pt frame sits 5.5 pt into the 18 pt gauge, and the layout rounds each frame to the pixel grid on its own, so at 1x and 3x the inner ring was drawn 0.5 px right of and below the outer ring's centre (at 2x it lined up, but not in a taller pill whose gauge isn't 18 pt). Arcs in warning or critical color make it visible. Fix: every ring (and the ring key, and the widget gauge) is a `RingShape` drawn in the gauge's own square around its centre. `RingCentringTests` fits a circle to each ring's pixels in the pill at 22/24/30 pt and 1x/2x/3x, at 88 % and 97 % and with one ring colored: the centres are within 0.25 px (measured: under 0.07 px; 1.0's layout fails the test).
- **Taller pill (note 8).** `PillMetrics(height:)`: at least 22 pt; the app passes `PillMetrics.height(forMenuBar:)` (the menu bar's height minus 6 pt). Everything scales with `height / 22` and is rounded: gauge (even points, so its centre is on the pixel grid), dot, text, symbols, paddings, spacing and the text caps (moment 212 pt, needs-you name 88 pt / 56 pt with one gauge per tool, at 22 pt). Renders, store screenshots and marketing use 24 pt (`PillMetrics.standardHeight`) in a 30 pt mock menu bar; `PillView` defaults to 22 pt.
- **Motion (note 7).** `PillMotion` (HeadroomUI, pure) plans each change: between different layouts (normal, moment, needs-you rest state) three steps: old text fades out (0.12 s), the item's length and the gauge move to the new layout with text hidden (0.3 s), new text fades in with a 3 pt slide (0.18 s). Growing therefore widens before the text shows and shrinking hides the text before it narrows. Within one layout, and with Reduce Motion, changes are immediate. Pills that arrive during a transition are coalesced (only the newest waits). The app draws each step with `PillView(textOpacity:fillsWidth: true)`, where the capsule fills the item's stepped width and clips what doesn't fit yet, and steps `NSStatusItem.length` with `PillMotion.progress(_:)` (cubic ease-out, the same curve as `PillMotion.animation(duration:)`).

### 14.11 Background tasks keep a session working (Nio, 2026-10-05) [V-local]
A Claude session whose turn ended while a background task still ran showed as Idle, though Claude's own panel said "1 running task". The registry has no field for it (`status:"idle"`). Now an idle Claude session (registry or bridge) counts as **working** when either holds; waiting sessions stay waiting:
- **Shell child.** Claude Code runs every Bash tool command, background task and monitor in a shell it spawns itself (`bash`/`zsh`/`sh`/`fish`/`dash`/`ksh`/`tcsh`/`csh` as `p_comm`); MCP servers are `node`/`npm`/… children. `ProcessProbing.shellParents()` reads `sysctl KERN_PROC_ALL` once per build (already used for §14.3, sandbox-safe). Checked live: of 13 running sessions only the one with a background render had a shell child.
- **Background agent.** `<transcript>/subagents/agent-<id>.jsonl` written in the last 10 minutes whose newest `user`/`assistant` line is not an assistant line with a final `stop_reason` (`end_turn`, `stop_sequence`, `max_tokens`, `refusal`). The 10-minute bound drops agents stopped or interrupted mid-turn.
- Known trade-off: a dev server left running in the background keeps its session working until it stops, matching Claude's own running-task count; the finish moment comes when the last background task ends and Claude's follow-up turn completes.

### 14.14 Just finished (Nio, 2026-10-18, 1.1.1)
